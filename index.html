tencent-docx

专业 Word / Docx / DOCX 文档（.docx）创作与美化助手。当用户需要生成、创作、排版或美化 Word / Docx / DOCX 文档（.docx 文件）时必须调用。核心能力：(1) 生成专业 Word 文档 —— 从零创作研报 / 论文 / 公文 / 合同 / 商务报告 / 会议纪要等垂类专业 .docx，自带专业封面与版式；(2) 专业美化 Word 文档 —— 对已有 Word / Docx / DOCX 文档进行专业排版美化，调整版式、优化视觉层级、统一格式风格；(3) 输出交付 —— 导出专业 .docx / Word 文档。不适用：纯代码文件、非 Word / Docx 类操作。触发词：写 Word、生成 Word、写 Docx、生成 DOCX、生成 .docx、创作 Word 文档、写文档、生成文档、起草报告、写研报、写论文、写合同、写公文、Word 排版、Docx 排版、DOCX 美化、Word 美化、Word 排版美化、Docx 排版美化、美化 Word 文档、美化 Docx 文档、美化 DOCX、美化 .docx、专业美化 Word、专业 Word 排版、加封面、调整 Word 版式、导出 Word、导出 Docx、导出 DOCX、导出 .docx

  • 按 orchestrator Stage 0 判断入口类型
  • 按 Stage 链路由到对应 Agent/Skill
  • 由下游 Skill（doc-typeset / html-to-docx 等）决定具体工具调用
  • 生成专业 Word / Docx / DOCX 文档：从头创作研报 / 年报 / 论文 / 公文 / 合同 / 商务报告 / 会议纪要等垂类专业 .docx，自动生成封面、目录、专业排版。
  • 专业美化 Word / Docx / DOCX 文档：对已有 Word 文档进行专业排版美化 —— 调整版式结构、优化视觉层级、统一字体字号、规范表格与图片、生成专业级视觉呈现。

doc-typeset

接收上游 design-token skill 的 token 输出和原始文档内容，输出排版美化的完整 HTML 字符串。

  • 命中 → 加载 prompts/{genre}.md（排版 prompt）+ templates/{genre}.html（HTML 骨架）
  • 未命中 → 加载 prompts/base.md + templates/base.html
  • 字体大小：--fs-{level}（如 --fs-h1、--fs-body）
  • 字体族：--ff-{type}（如 --ff-heading、--ff-body）
  • 颜色：--color-{name}（如 --color-primary、--color-text）
  • 间距：--spacing-{name}（如 --spacing-paragraph、--spacing-section）

underline-toolkit

生成带下划线填空位的 Word 文档（create 模式）或对已有下划线模板回填数据（fill 模式）。适用于合同、协议、申请表、有封面的文档（如毕业论文）等。触发关键词：下划线、填空、下划线模板、合同填空、表单回填、下划线回填。

  • create 模式：addunderlinerun() 不传 value（或 value=""）→ 空白下划线
  • fill 模式：addunderlinerun(value="实际内容") → 内容 + 下划线保留

nano-banana-expert

通过指导agent智能调度 Nano-Banana 模型，针对\"照片级真实感、皮肤质感还原、旧照片修复、人物肖像、产品实拍\"等场景深度优化 prompt 工程，输出照片级还原的真实感视觉与商业级人像摄影，擅长自然皮肤纹理、眼神光与镜头语言术语。

  • 不接收参数；返回账户与余额摘要
  • modelType（可选，string）：资源类型枚举 TEXT / IMAGE / VIDEO（本 Skill 用 IMAGE）
  • path（必填，string）：用户授权的本地文件绝对路径
  • filename（可选，string）：覆盖上传文件名
  • contentType（可选，string）：覆盖 MIME 类型；不确定时省略并由客户端识别
  • publicModelId（必填，string）：来自 listmodels(modelType="IMAGE") 的当前模型 ID

resume-diagnosis

用于诊断、评审或评分整份简历。当用户要求「诊断简历」「简历有什么问题」「看看简历哪里要改」「简历打分」「评审简历」「resume review」，或上传 PDF/DOCX 并要求分析问题、给出评分或修改建议时触发。输出 3 类诊断（NO_DATA / NO_FILL / DESCRIPTION_SUGGEST）和 6 维评分（简历完整度 / 经历描述 / 学习能力 / 专业能力 / 创新领导力 / 职场能力），诊断与评分规则及配置见 `references/`，全程由确定性脚本 + 一次批量 LLM 推理完成。仅诊断、评分和提出建议，不直接重写整份简历或生成优化版；用户明确要求改写、润色、优化内容或生成新版简历时，改用 resume-ai-help。

  • 诊断（3 类问题）：NODATA / NOFILL / DESCRIPTIONSUGGEST；
  • 评分（6 维分数）：简历完整度 / 经历描述 / 学习能力 / 专业能力 / 创新领导力 / 职场能力；
  • 报告输出：一份 HTML 诊断报告（score / beatPercent / reportDetails）。
  • scripts/orchestrate.py 合并「(finalize) → 注入 LLM 结果 → build-report → 渲染 HTML → 校验」为一次调用。
  • 用户上传/粘贴简历并请求："帮我诊断"、"简历哪里有问题"、"帮我优化简历"、"简历打分"。
  • 用户问"这份简历能过 HR 初筛吗"。
